# Dexhaven v0.4.0 — Pokémon Encyclopedia

The shared Pokémon dialog now contains **Overview**, **Base Stats**, **Evolutions**, **Moves**, **Type Matchups** and **Pokédex Information** sections. It is available from the National Pokédex, Trainer Hub favourites, dashboard rankings and comparison cards. The main catalogue and trainer API still accept only National species #001–649.

## Usage and local review

Install dependencies if needed, restart Express with `npm.cmd start`, and open http://localhost:3000/pokemon.html?pokemon=1. No login is required for the encyclopedia. The **Shareable entry** link always points to the currently displayed Pokémon on `pokemon.html`; relative assets and links also work under a GitHub Pages repository subpath. Invalid/out-of-scope shared IDs display a clear message rather than opening unsupported entries.

- Use the six section buttons, Tab, Left/Right arrows, Home and End. Only the selected section is displayed. Escape closes the native dialog, and the original card retains native focus restoration. Previous/Next and evolution navigation place focus on the new heading after it renders. Previous/Next stop at #001 and #649.
- Open Bulbasaur's Evolutions to inspect the three-stage family and level requirements. Open Eevee (#133) for branches, stones, friendship/day/night, location and other recorded conditions. Sylveon (#700) remains visible with artwork and a **Beyond #649 · reference only** label; it is not a clickable catalogue/trainer entry. Genesect (#649) has a clear no-evolution state.
- In Moves, choose a Generation I–V game group and filter by name, type, Physical/Special/Status category or learning method. Sort by name, required level, power, accuracy or PP. The current game label is displayed above results. Each row represents one move/method/level combination **in that game group**; multiple learning methods remain separate. Previous/Next moves paginate 24 rows at a time.
- Compare Tackle in Red/Blue (35 power, 95% accuracy) and Black/White or Black 2/White 2 (50 power, 100% accuracy). These are historical values supplied by PokéAPI, not the current move's 40 power. Thunderbolt is 95 power in Generation V. Status moves or variable/not-applicable values display a dash, not a fabricated zero. Level zero or absent levels display a dash instead of inventing an evolution-level requirement.
- In Type Matchups, Charizard (#006) has a 4× Rock weakness, 0.25× Grass resistance and Ground immunity. The defensive table includes all 18 attacking types, with weakness/resistance/neutral/immunity labels. Offensive tables are separate for each of the Pokémon's own types and target a **single defending type**; they do not claim to describe the actual moveset's coverage.
- In Pokédex Information, inspect classification, introduction/region, measurements, abilities/hidden flags, base experience, capture rate, friendship, growth, egg groups, gender, habitat and legendary/mythical status. Choose an English game entry to change the description. Missing values say **Not recorded**, and genderless species are distinct from an unknown ratio.

## Source, rules and historical scope

All new resource data comes from the [official PokéAPI v2 endpoints](https://pokeapi.co/docs/v2): `pokemon-species`, `evolution-chain`, `pokemon`, `move` and `type`. Individual families and type interactions are not hardcoded. Evolution resources retain complete branches and later-generation species. Evolution requirement alternatives are displayed separately with game-group labels when provided. Known conditions include levels, stones, held items, friendship, affection/beauty, time, gender, trading, required moves/types, location/party, physical-stat relationships, rain, device orientation, forms/region, multiplayer, steps, move-use counts, damage and natures. Additional structured conditions are displayed as recorded rather than guessed or evaluated; availability can vary by game/form.

Movesets are restricted to the Generation I–V version groups available for the species, including Colosseum/XD. Later groups are not merged in. Move metadata is adjusted backwards using PokéAPI `past_values` change boundaries. Chronological exceptions for Colosseum/XD, FireRed/LeafGreen/Emerald and Japanese Gen I groups are handled explicitly because resource IDs are not a complete chronological ordering. Damage categories before Generation IV use the historical type-based split; Status remains Status. The API can omit historical changes, so displayed labels explain that historical metadata may have gaps. This is not a guarantee of exhaustive competitive legality, transfer paths, machine numbering or game/form availability.

Type matchups use **modern Generation VI-onward type relations** and the displayed current typings. They deliberately differ from historical Gen I–V mechanics. Multiply each defending type's incoming relation (0, 0.5, 1 or 2) to obtain 0, 0.25, 0.5, 1, 2 or 4; a zero factor always preserves immunity. Abilities, items, weather, battle-specific effects and STAB are outside these tables. Offensive relations describe type effectiveness alone.

Base stats retain the existing current-data detail/snapshot behavior. Capture, friendship and base experience are the currently recorded resource values, not historical game-specific promises. Descriptions have their own explicitly labelled English game selector. Newlines/form-feed controls are normalized; API content is inserted as text, never interpreted as HTML.

## Loading, caching and race protection

`encyclopedia-data.js` provides one shared request scheduler with **at most four concurrent requests**, 12-second timeouts, response validation and per-resource in-flight coalescing. New data is fetched only after a corresponding section is activated. Opening Overview/Base Stats does not fetch species, evolution chains, move metadata or type relations.

Successful resources are cached in memory and in localStorage for seven days under `dexhaven-encyclopedia-v1-*`. Species records retain needed fields and English text only; raw Pokémon records retain base experience and Generation I–V learn-method summaries only; type resources retain relations and move resources retain their historical values. Full evolution families share the same chain-ID cache across related Pokémon. Blocked/full storage falls back to memory, and malformed, future-dated, mismatched and expired cached responses are refetched. Existing catalogue, detail, analytics and theme keys are preserved. To refresh encyclopedia data early, remove only keys with this prefix in browser developer tools and reload.

When the existing detail request already contains move summaries, it seeds this cache, avoiding a duplicate Pokémon request. Old detail caches and the analytics snapshot do not include learnsets; they require one on-demand Pokémon resource request when the new information is first needed. No movesets for the complete catalogue are downloaded at startup.

The initial Moves view fetches metadata only for its current 24-row page. Name/method searches narrow summaries before metadata is fetched. Type/category filtering and numeric sorting need metadata for all matching entries in the selected game's learnset; they load it in bounded batches, show progress and reuse the shared cache. This can require multiple requests the first time. Failures expose Retry moves and do not present incomplete filtered results as a completed search.

Each dialog render owns its section nodes. Detached/closed dialogs cannot receive late results. Each move-filter/version change also has a revision token so earlier searches cannot overwrite a newer one. New Pokémon selection uses the existing detail revision guard. Requests shared by other consumers may finish and populate caches, but stale renderers stop queuing subsequent batches. Cached successes survive retries; failures are not cached.

## Files and testing

New files: `encyclopedia-data.js`, `encyclopedia.js`, `tests/encyclopedia.test.cjs`, `tests/fixtures/encyclopedia.json` and this guide. Modified files: all four HTML pages for shared script loading, `script.js` for enhancement/cache/focus hooks, `styles.css`, Express's explicit asset allowlist, package version metadata, backend/browser/upgrade tests, the shared fixture factory and project documentation. Existing authentication, schema, repository/session logic, analytics snapshot and founder artwork are preserved.

Run `npm.cmd test` and `npm.cmd run test:browser`. Tests cover standard/branching/standalone and later-generation evolution relationships, condition formatting, isolated version-group learnsets, historical move values, dual-type multipliers/immunity precedence, missing optional data/English entries, cache persistence/coalescing/concurrency/retries, deep links, keyboard/focus, stale responses and layouts in both themes. Representative species cover all five generations. The browser suite uses deterministic resources and isolated test accounts/session stores/uploads. Its real PokéAPI samples deliberately restrict learnsets to included metadata for repeatability; runtime learnsets are not restricted to that sample.

The live-MySQL suite remains opt-in and no migrations or live database writes are performed for this update. Before publishing, manually verify real device/screen-reader behavior, Safari/Firefox, current live PokéAPI data and your existing authenticated account. No push, deployment or GitHub release is triggered.
